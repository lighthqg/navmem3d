# NavMem3D 项目进展与后续计划

更新日期：2026-09-12

## 当前目标

NavMem3D 验证这样一条工程链路：机器人先在一个房间内巡视，巡视图像交给 Marble 或其他三维重建器形成数字孪生 B；B 负责抽取和查询实体语义；机器人自己的地图 M 负责观测空间、路线连通和执行。评测场地 A 只负责提供仿真传感器和独立真值。

```text
A：RGB + 深度/LiDAR + 里程计/VIO + 隐藏评测真值
        ├──> B：Marble 三维语义世界、实体、虚拟视角
        └──> M：机器人观测空间层、巡视拓扑、参考关键帧
                         ↑
                         └── B 的实体绑定到 M 的观察节点
```

## 已完成

### 1. 工程框架

- `WorldManifest`、`CaptureSequence`、实体索引、目标索引和路线 JSON 契约；
- 世界包检查、关键帧选择、3DGS 资产检查和统一 CLI；
- CUDA 3DGS 渲染入口与逐像素 Gaussian contributor ID 输出；
- 中文/英文关键词、属性和显式空间关系查询。

### 2. 餐厅单房间原型

- A 场景：InteriorGS `0001_839920`；
- 巡视输入：300 帧轨迹，8 张 Marble 输入关键帧和 30 秒视频接口；
- 视觉路线图：22 个关键帧节点、21 条实际巡视的可逆边；
- 可靠拓扑骨架：41 个节点、48 条无向边，作为当前路线基线；
- Marble 实体交接：48 个实体完成到路线观察节点的绑定，其中 33 个标记为 `navigation_eligible=true`；
- 示例路线：从 `topo_000` 到餐桌候选 `topo_039`，再到 `topo_001`，路线代价字段和参考帧序列已经落盘；
- 联合可视化：空间层（free/occupied/unknown 与障碍轮廓）叠加拓扑节点、无向边和路线高亮。

### 3. 已有验证结果

- 留出巡视帧视觉重定位：42 帧查询中 39 帧成功，定位率 92.9%；成功帧的路线边关联率 100%；
- 餐桌路线回放：12 个参考节点全部在自身 RGB 回放中定位成功（12/12）；
- 20 项契约测试通过，Python 源码编译检查通过。

这些结果只说明接口连通和同域离线 repeatability。它们没有证明控制器在未知起点、动态障碍、跨域图像或真实机器人上能够成功导航。

## 已知限制

1. `observed_map` 的深度目前含 CPU Gaussian center z-buffer fallback，深度覆盖不足；由它自动提取的 `topology_graph_observed.json` 是诊断失败实验，不能替代 41/48 路线基线。
2. 当前正式导航路线仍依赖已验证的巡视拓扑；从观测 occupancy 自动抽骨架还未达到验收标准。
3. Marble B 与 A/M 的坐标注册仍是实验接口，不能把 B 的几何坐标直接当成控制器地图坐标。
4. 起点目前是协议给定的拓扑节点。随机起点全局重定位、长距离漂移修正和真实控制器尚未完成。
5. 单房间结果不能代表多房间或大尺度场景；跨多个 Marble 世界的拼接暂不纳入第一版结论。

## 后续评测路线

### 阶段 E0：固定餐厅、固定路线的回归测试

目的：保证工程改动不破坏已经存在的契约和路线。

- 每次运行固定保存 `run_manifest.json`、代码 commit、配置、输入哈希和输出哈希；
- 回归检查：图节点/边数量、无向边对称性、孤立节点数、目标绑定数量、路线是否可达；
- 通过条件：20 项契约测试全部通过，正式路线 JSON 可被 CLI 读取，联合图可重新渲染。

### 阶段 E1：空间层质量评测

目的：把“障碍物大概轮廓”和“可通行区域”从展示变成可量化输入。

- 在 A 中渲染 RGB-D 和模拟 LiDAR，机器人地图只消费这些观测与 VIO/里程计；
- 对比独立评测真值，统计 free/occupied/unknown 的 precision、recall、IoU、覆盖率；
- 统计障碍轮廓偏差、自由空间连通分量数、错误孤岛数和虚假捷径数；
- 做传感器消融：RGB-only、RGB-D、LiDAR-only、RGB-D+LiDAR；
- 通过条件：主巡视区域覆盖率达到预设阈值，未知区不被路线规划使用，不能出现未巡视房间的孤立连通分量。

### 阶段 E2：拓扑与路线评测

目的：验证图数据表达的是实际连通性，并能在不同起终点给出近似短路。

- 从 41/48 基线开始，加入节点合并、分叉节点补全和边 polyline 清理；
- 以 A 的隐藏 navmesh/碰撞结果只作为评测器，计算路线碰撞、成功到达率、路径长度、最短路比值和重规划次数；
- 起点从已知节点扩展到节点附近扰动，再扩展到随机已观测自由空间位置；
- 比较 Euclidean 最近邻、轨迹折线图、观测 occupancy 骨架和最终无向拓扑四种路线图；
- 重点回归 `T023 → T004` 等容易产生虚假捷径的节点对。

建议的核心指标：

```text
success_rate = 到达目标观察区域且最终 RGB 确认的任务数 / 总任务数
collision_rate = 发生碰撞的任务数 / 总任务数
path_ratio = 实际路线长度 / 评测器最短可行路线长度
graph_coverage = 可从拓扑图到达的已观测自由空间比例
```

### 阶段 E3：语义查询与交接评测

目的：验证实体是否能正确交给导航图，而不是只看 3D 渲染效果。

- 关键词目标：`餐桌`、`吊灯`、`冰箱`等类别级查询；
- 带限定目标：类别 + 颜色/尺寸/区域；
- 关系目标：类别 + `near/left_of/in_room` 等已支持关系；
- 每个实体分别评测检测、实例去重、观察节点绑定和最终当前 RGB 确认；
- 统计漏检率、重复实例率、错误绑定率、无导航资格比例和查询延迟；
- 对 Marble 虚拟视角数量做消融：4/8/16/32 视角，优先观察“新增实体召回”而不是只看图像质量。

### 阶段 E4：视觉执行与起点定位

目的：从“已知拓扑节点回放”推进到机器人可执行的路线。

- 起点类型：已知节点、节点附近扰动、已观测区域随机起点；
- 执行输入只允许当前 RGB、短期 odometry/VIO 和路线参考帧；
- 测试光照变化、图像压缩、相机视角扰动、局部遮挡和短时跟踪丢失；
- 记录重定位耗时、漂移、错误边选择、恢复次数、停车次数和最终目标确认；
- 先做仿真控制器，再接真实录制数据，最后才考虑实体机器人。

## 训练计划

第一版不需要训练一个新的世界模型。Marble、3DGS 渲染器、Grounding DINO 和 SAM2 先作为固定后端，训练资源集中在会直接影响导航闭环的模块。

### T0：不训练，建立可复现实验基线

- 固定词表和显式关系查询；
- 固定 4/8/16 视角语义编译；
- 先完成 E0-E3，形成可比较的 JSON ledger 和失败样例集；
- 所有训练数据必须来自机器人可见观测，不能用 A 的 labels/structure 作为模型输入。

### T1：训练/校准实体到观察节点的绑定器

训练目标是判断一个 Marble 实体是否能由某个巡视节点可靠观察，而不是预测世界坐标。

- 输入：虚拟视角与巡视 RGB 的局部匹配、尺度、视角差、遮挡、清晰度和拓扑邻域特征；
- 标签：由人工复核或严格评测协议给出的“可观察/不可观察/不确定”；
- 模型：先用 logistic regression/GBDT 校准分数，数据足够后再尝试轻量 MLP；
- 输出：`binding_confidence`、候选节点排序和 `navigation_eligible`；
- 切分：按房间划分 train/validation/test，不能把同一房间的相邻帧随机打散后冒充跨场景泛化。

### T2：训练视觉路线重定位器

- 先以 SIFT/RANSAC 作为可解释基线；
- 使用巡视 RGB 与受控增强图像构造正负样本：亮度、模糊、压缩、遮挡、视角小扰动；
- 训练轻量图像检索/局部匹配模型，只负责节点或边候选排序；
- 保留几何一致性验证和安全阈值，低置信度只能触发复观察或停车；
- 评测重点是错误边率、恢复时间和跨域下降，而不是单纯 top-1 分类准确率。

### T3：可选的语义 3D 后端训练

只有当 E3 证明固定词表召回成为瓶颈时，才引入 OpenSplat3D/LangSplat 类训练后端：

- 训练目标是提高 3D 实例召回、跨视角一致性和未知类别查询，不改变 M 的路线数据结构；
- 先在公开/合成场景做预训练或复现实验，再用真实观测做小规模适配；
- Marble 仍作为高质量 B 世界来源，训练后端作为语义增强或未命中兜底；
- 必须报告训练耗时、显存、视角数量、实例召回和查询延迟，不能只展示更好看的渲染图。

## 推荐执行顺序

```text
1. E0 回归基线与运行记录
2. E1 真实 RGB-D/LiDAR 观测 occupancy
3. E2 41/48 无向拓扑的多起点路线评测
4. E3 Marble 实体查询与节点绑定全量评测
5. E4 视觉执行、起点扰动和漂移恢复
6. T1 绑定器校准
7. T2 重定位器训练
8. 多房间/ScanNet++ 扩展
9. 只有在语义召回不足时开展 T3
```

## 结果交付格式

每个实验目录应至少包含：

```text
run_manifest.json       # commit、配置、输入哈希、环境版本
metrics.json            # 统一指标
events.jsonl            # 每一步定位、查询、规划和执行事件
route.json              # 实际规划路线
failure_cases/          # 可复核的图像、实体或路线失败样例
visualization/          # 联合地图、路线和时间线
```

正式报告只引用可由上述文件复核的结果；诊断 fallback、A 隐藏真值接线和人工修补结果必须单独标明。
